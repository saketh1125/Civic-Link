# Civic-Link DPI - Database Schema

## Overview

Civic-Link uses **PostgreSQL 16** with **PostGIS 3.4** extension for geospatial capabilities. All geographic data uses the `Geography` type (not `Geometry`) with SRID 4326 for accurate earth-surface calculations.

### 5. civic_scores

**Purpose:** Driver behavior scoring

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| id | VARCHAR(36) | PRIMARY KEY | UUID generated by application |
| user_id | VARCHAR(36) | FK users.id, UNIQUE, NOT NULL | Driver being scored |
| score | FLOAT | DEFAULT 100.0, NOT NULL | Current civic score (0-100) |
| total_trips | INTEGER | DEFAULT 0 | Total completed trips |
| total_distance_km | FLOAT | DEFAULT 0.0 | Total distance driven |
| total_driving_hours | FLOAT | DEFAULT 0.0 | Total driving time |
| swerve_count | INTEGER | DEFAULT 0 | Lane-cutting events (gyro_z > 1.5 rad/s) |
| speeding_count | INTEGER | DEFAULT 0 | Speeding events |
| hard_braking_count | INTEGER | DEFAULT 0 | Hard braking events |
| rapid_acceleration_count | INTEGER | DEFAULT 0 | Rapid acceleration events |
| last_swerve_at | TIMESTAMP | NULL | Last swerve event (for cooldown) |
| last_speeding_at | TIMESTAMP | NULL | Last speeding event |
| last_hard_brake_at | TIMESTAMP | NULL | Last hard brake event |
| swerve_penalty | FLOAT | DEFAULT 0.0 | Penalty points from swerves |
| speeding_penalty | FLOAT | DEFAULT 0.0 | Penalty points from speeding |
| last_calculated_at | TIMESTAMP | DEFAULT NOW() | Last score calculation |
| calculation_version | VARCHAR(10) | DEFAULT '1.0' | Scoring formula version |
| is_active | BOOLEAN | DEFAULT TRUE | Soft delete flag |
| created_at | TIMESTAMP | DEFAULT NOW() | Creation timestamp |
| updated_at | TIMESTAMP | DEFAULT NOW() | Last update |

**Indexes:**
- `ix_civic_scores_score` on `score`
- `ix_civic_scores_swerves` on `swerve_count, score`

**Scoring Formula (Weighted Penalty Model):**
```
Score starts at 100, penalties deducted:
- Speed penalty: clamp(mean(speed_kmh) - 60, 0, 40) * 0.4
- Hard brake: count(braking_ms2 > 4.0) * 2.0
- Acceleration: count(acceleration_ms2 > 3.5) * 1.5
- Swerve: mean(swerve_index > 0.3) * 10.0
- Phone usage: count(phone_usage_detected) * 5.0

Blended: (old_score * 0.7) + (new_score * 0.3)
```

**Encryption:**
- Algorithm: AES-256-GCM (via `cryptography` library)
- Key: 32-byte hex from `AUDIT_LOG_ENCRYPTION_KEY` env var
- IV: 12-byte random per record
- Plaintext includes: user IDs, locations, timestamps, event metadata

## Geospatial Considerations

### SRID 4326 (WGS 84)

- **Standard:** World Geodetic System 1984
- **Used by:** GPS, Google Maps, most mapping systems
- **Unit:** Degrees latitude/longitude
- **Conversion:** PostGIS automatically converts to meters for calculations

### Why Geography Instead of Geometry?

| Type | Calculations | Use Case |
|------|--------------|----------|
| Geometry | Cartesian (degrees) | Map projections, flat surfaces |
| Geography | Spherical (meters) | Real-world distances on Earth |

**Civic-Link uses Geography** because:
1. `ST_DWithin(origin, point, 500)` returns true if within 500 **meters**
2. No manual degree-to-meter conversion needed
3. Accurate for the ~10km KPHB to HITEC corridor

### Example Queries

```sql
-- Find commutes starting near KPHB Phase 3 (500m radius)
SELECT c.*, u.full_name, u.gender
FROM commutes c
JOIN users u ON c.driver_id = u.id
WHERE ST_DWithin(
    c.origin,
    ST_SetSRID(ST_MakePoint(78.4020, 17.4930), 4326)::geography,
    500
)
AND c.status = 'active'
AND c.available_seats > 0;

-- Calculate distance between two points
SELECT ST_Distance(
    ST_SetSRID(ST_MakePoint(78.4020, 17.4930), 4326)::geography,
    ST_SetSRID(ST_MakePoint(78.3770, 17.4430), 4326)::geography
) / 1000 AS distance_km;
-- Result: ~8.2 km
```

## Performance Optimization

### Indexing Strategy

1. **B-tree indexes:** For equality/range queries (status, dates)
2. **GIST indexes:** For geospatial queries (ST_DWithin)
3. **Composite indexes:** For multi-column filters

### Query Optimization

1. **selectinload:** Eager loading for related entities
2. **Bounding box filter:** Pre-filter before ST_DWithin
3. **Connection pooling:** asyncpg with 20+ connections
